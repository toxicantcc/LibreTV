# LibreTV × 鸿蒙原生体验：个人学习路线

> 适用前提：你已实践过 **PWA / 添加到桌面**、**uni-app + `web-view` 壳**，希望进入 **ArkTS + ArkUI** 为主的「原生体验」学习。  
> 本文档仅供 **个人学习、私有环境** 使用；请勿用于公开商用或侵犯版权的场景。部署与接口设计请遵守当地法律与内容授权规则。

---

## 一、目标定义

| 维度 | 目标 |
|------|------|
| 体验 | 主流程（搜索 → 列表 → 详情 → 播放）以 **ArkUI 原生组件** 呈现，避免整站塞进 `Web` |
| 技术 | 掌握 **Stage 模型**、**声明式 UI**、**HTTP 数据层**、**媒体播放**、基础工程化 |
| 与 LibreTV 关系 | 鸿蒙端为 **新客户端**；数据来自你 **自建/本地可访问的 HTTPS API**（可由现有 `server.mjs` 演进或独立 mock） |

---

## 二、环境与工具（以官方文档为准）

1. 安装 **DevEco Studio**（版本与 SDK 要求以 [HarmonyOS 应用开发文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/application-dev-guide) 为准）。
2. 准备 **HarmonyOS NEXT**（或你设备对应的 API 级别）**真机** 与开发者调试能力（签名、USB/无线调试）。
3. 准备可访问的 **HTTPS 后端**（局域网穿透、云主机、或纯本地 mock 服务均可），用于练习真实网络栈。

**说明**：具体 API 包名（如网络、媒体）随 SDK 版本可能调整，以下里程碑以「能力名称」为主，实现时请在 DevEco 内联文档或官网检索对应模块。

---

## 三、里程碑 1：原生工程骨架

### 3.1 任务清单

- [ ] 创建 **Stage 模型** 工程（Empty Ability 即可）。
- [ ] 跑通 **真机调试**（证书、安装、日志 `hilog`）。
- [ ] 实现 **双页导航**：例如「首页（占位）」↔「列表页（占位）」。
- [ ] 统一 **主题色 / 状态栏 / 安全区**，避免刘海遮挡标题栏。

### 3.2 验收标准

从桌面图标进入应用，**全程无整页 `Web` 作为主界面**；页面切换流畅，旋转屏幕布局不崩。

---

## 四、里程碑 2：网络与列表（对接后端）

### 4.1 任务清单

- [ ] 封装 **HTTP 客户端**（超时、错误码、JSON 解析），建议单独目录：`service/`、`model/`。
- [ ] 定义与后端一致的 **数据模型**（如：`SearchItem`、`Episode`、`Detail`）。
- [ ] 列表页使用 **`List` + `LazyForEach`**（或当前 SDK 推荐的懒加载列表方案）。
- [ ] 增加 **下拉刷新**、**加载中**、**空数据**、**失败重试**。

### 4.2 建议的 API 形态（学习用）

以下为示意，字段名可按你后端调整：

```http
GET /api/search?q={keyword}&page={n}
```

响应示例（节选）：

```json
{
  "items": [
    { "id": "string", "title": "string", "cover": "https://...", "year": "string" }
  ],
  "page": 1,
  "hasMore": true
}
```

```http
GET /api/detail?id={id}
```

```json
{
  "id": "string",
  "title": "string",
  "cover": "https://...",
  "intro": "string",
  "episodes": [{ "index": 1, "title": "string", "playUrl": "https://..." }]
}
```

### 4.3 与现有 LibreTV 的衔接方式

| 方式 | 说明 |
|------|------|
| A. 演进 `server.mjs` | 在现有代理/搜索逻辑之上 **增加只返回 JSON 的路由**，专供鸿蒙客户端。 |
| B. 独立 BFF | 另起一个小服务，只做 **聚合与裁剪**，LibreTV 网页仍走原逻辑。 |
| C. 纯 Mock | 先用静态 JSON 或 `json-server` 类工具把 **UI 与播放器** 练熟，再换真实接口。 |

### 4.4 验收标准

在弱网（限速）下列表 **不白屏**；错误有明确提示；列表滚动 **无明显掉帧**（数据量可先控制在几百条内）。

## 五、里程碑 3：详情页与播放（原生体验核心）

### 5.1 详情页

- [ ] 海报（`Image` + 缓存策略或占位图）、标题、简介、标签区。
- [ ] 选集 **网格或列表**；点击某一集进入播放页或同页内嵌播放器区域。

### 5.2 播放

- [ ] 优先使用 **`@ohos.multimedia.media`（AVPlayer）** 或当前文档推荐的 **流式播放** 能力，支持你的 `playUrl` 实际格式（如 HLS、直链 MP4 等以实测为准）。
- [ ] 处理 **全屏**、**进度条**、**暂停/继续**、**播放结束** 与 **返回栈**（从全屏返回列表状态正确）。
- [ ] 若个别片源 **仅能在网页环境播放**：可 **单独** 使用 **`Web` 组件** 承载该播放页，但 **搜索/列表/详情仍保持 ArkUI**（混合策略，学习价值高）。

### 5.3 验收标准

从搜索到连续播放多集 **无需手动复制链接**；旋转全屏、来电或切后台行为符合预期（按系统策略文档处理生命周期）。

---

## 六、里程碑 4：体验与工程化收尾

### 6.1 任务清单

- [ ] **偏好存储**：记录上次关键词、上次观看集数（`preferences` 或轻量数据库，按官方推荐选型）。
- [ ] **图片与内存**：列表封面尺寸、解码策略，避免 OOM。
- [ ] **权限声明**：网络、媒体相关权限在 `module.json5` 中 **最小化、可解释** 地配置。
- [ ] **适配**：手机 / 折叠屏 / 平板可用 **栅格与断点** 做简单布局分栏（例如平板左侧列表右侧详情）。

### 6.2 验收标准

冷启动到首屏可交互时间可接受；无未捕获崩溃；主要路径在 **深色模式** 下可读（若系统支持）。

---

## 七、可选路线：uni-app x（非必须）

若你希望 **一套代码覆盖多平台** 且鸿蒙侧更接近原生渲染，可另行学习 **uni-app x（UTS + uvue）** 与鸿蒙编译链。  
这与 **纯 ArkTS** 路线二选一即可，避免两条线并行导致时间分散。

---

## 八、学习顺序小结（执行顺序）

1. 里程碑 1：工程 + 导航 + 真机。  
2. 里程碑 2：Mock 或真实 API + 列表。  
3. 里程碑 3：详情 + AVPlayer（必要时局部 `Web`）。  
4. 里程碑 4：存储、权限、适配与稳定性。

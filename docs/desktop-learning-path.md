# LibreTV × 桌面端：个人学习路线

> 适用前提：你希望练习 **「安装包 + 本地窗口 + 自带 Node 后端」**，而不是仅打开浏览器访问远程站点。  
> 本文档仅供 **个人学习、本机或局域网私有使用**；请勿将带代理能力的实例暴露公网。README 要求生产环境设置 **`PASSWORD`**，学习时也应养成习惯。

---

## 一、目标定义

| 维度 | 目标 |
|------|------|
| 体验 | 双击图标启动 **桌面壳**，自动拉起 **Express（`server.mjs`）**，窗口内打开 **本地地址**（如 `http://127.0.0.1:8080`） |
| 技术 | 掌握 **子进程管理**、**端口就绪检测**、**壳与系统托盘/单实例**（可选）、**安装包构建** |
| 与 LibreTV 关系 | 壳项目 **引用本仓库** 或打包后的 `server.mjs` + 静态资源；默认端口见下节 |

本仓库服务端为 **Node + Express（ESM）**，默认端口：

```text
PORT（环境变量）或 8080
```

见 `server.mjs` 中 `process.env.PORT || 8080`。

---

## 二、技术选型（二选一即可）

| 方案 | 优点 | 注意点 |
|------|------|--------|
| **Tauri 2.x** | 安装包相对小、系统 WebView、Rust 侧管进程 | 需安装 Rust 工具链；子进程/IPC 用 **Tauri 插件或 Rust 命令** 实现 |
| **Electron** | 资料多、Node 与渲染进程同生态、spawn 示例极多 | 安装包体积大；注意 **安全模型**（`contextIsolation`、`preload`） |

**学习建议**：若你主攻 **进程编排与安装包**，任选其一练到底；不要同时开两条桌面线，避免时间分散。

---

## 三、环境与仓库准备

1. 本机已能独立运行：`node server.mjs`（或 `npm` 脚本），浏览器访问 `http://127.0.0.1:8080` 正常。  
2. 准备 **`.env`** 或壳内注入环境变量：至少熟悉 **`PASSWORD`**、**`PORT`**（与 README / `.env.example` 一致）。  
3. 安装 **Tauri 或 Electron** 官方文档要求的 **Node、包管理器、平台依赖**（Windows 上常见为 WebView2 / 构建工具链）。

## 四、里程碑 1：空壳 + 手动指定 URL

### 4.1 任务清单

- [ ] 创建 **Tauri / Electron** 最小工程，窗口加载 **固定 URL**（先手动 `node server.mjs`，再在壳里打开 `http://127.0.0.1:8080`）。  
- [ ] 区分 **开发模式**（加载 devServer 或本地 URL）与 **预览模式**。  
- [ ] 打开 **开发者工具** 的方式固定下来，便于调前端。

### 4.2 验收标准

不自动起后端的情况下：**先起 LibreTV 服务 → 再开壳**，页面与直接浏览器访问 **行为一致**。

---

## 五、里程碑 2：壳内自动启动 `server.mjs`

### 5.1 任务清单

- [ ] 在 **主进程**（Electron）或 **Rust 启动逻辑**（Tauri）中，使用 **`child_process.spawn` / `std::process::Command`** 启动 Node：  
  - `cwd` 指向包含 `server.mjs` 的目录；  
  - 使用与命令行一致的 **Node 可执行文件路径**（开发机 vs 打包后 `resources` 内嵌 Node 见下节）。  
- [ ] **端口占用**：若 `8080` 被占用，练习读取 `PORT` 环境变量或壳内生成随机端口，并把 URL 传给窗口。  
- [ ] **就绪检测**：轮询 `http://127.0.0.1:PORT/` 或监听子进程 stdout 中「listening」类日志（以你实际输出为准），**再** `loadURL`，避免白屏。  
- [ ] **退出清理**：窗口关闭或应用退出时 **SIGTERM / kill** 子进程，避免僵尸 Node 占端口。

### 5.2 打包后 Node 的两种常见做法（学习用）

| 做法 | 说明 |
|------|------|
| **依赖用户本机 Node** | 安装包小；要求 PATH 中有 `node`，不适合分发不熟悉环境的用户。 |
| **捆绑 Node 二进制** | 体积大；练习 **解压到 `resources`、spawn 绝对路径**、不同平台三件套（win/mac/linux）。 |

个人学习可先做 **本机已装 Node + spawn `node`**，再挑战 **捆绑二进制**。

### 5.3 验收标准

只双击桌面应用：**无需先开终端**，即可打开 LibreTV；退出应用后 **端口释放**，再次启动无冲突。

## 六、里程碑 3：配置、安全与体验

### 6.1 环境变量与配置界面（可选）

- [ ] 将 **`PASSWORD`**、**`PORT`**、**`DEBUG`** 等从 **`.env`** 或壳写入的环境传入子进程（`spawn` 的 `env` 字段）。  
- [ ] （进阶）做一个极简 **设置页**：首次启动写入本地配置文件，重启子进程生效。

### 6.2 安全基线（桌面同样重要）

- [ ] 默认仅监听 **`127.0.0.1`**（若你改 `server.mjs` 绑定，学习阶段务必理解 **勿 `0.0.0.0` 对公网`**）。  
- [ ] Electron：**禁用 `nodeIntegration` 于远程内容**；本地加载仍建议 **`contextIsolation` + `preload` 白名单 IPC**。  
- [ ] 不在日志中打印完整 **`PASSWORD`**。

### 6.3 体验增强（可选）

- [ ] **单实例**：第二次启动时聚焦已有窗口。  
- [ ] **系统托盘**：最小化到托盘、退出菜单。  
- [ ] **深链**：`libretv://play?...`（练习协议注册，非必须）。

### 6.4 验收标准

冷启动到可交互时间可接受；异常退出后 **无残留 Node**；主要操作无控制台报错（或错误有明确捕获）。

---

## 七、里程碑 4：安装包与分发（学习向）

### 7.1 任务清单

- [ ] **Windows**：`msi` / `nsis` 或 Tauri 默认打包流程，安装目录与卸载行为正常。  
- [ ] （若有条件）**macOS**：签名、公证概念粗读即可，个人学习可先 **本地 ad-hoc**。  
- [ ] 版本号：**`package.json` / tauri.conf.json** 与关于页一致。

### 7.2 自动更新（可选、后置）

Electron 有 `electron-updater` 等方案；Tauri 有官方插件。建议 **里程碑 1～3 稳定后再做**，避免与学习主线耦合过重。

### 7.3 验收标准

在一台 **干净虚拟机** 上安装运行成功（不依赖你开发机全局 Node，若你已做捆绑二进制）。

## 八、与鸿蒙路线的关系

| 路线 | 侧重点 |
|------|--------|
| 鸿蒙 ArkTS | 移动端原生 UI + 网络 + 媒体 |
| 桌面壳 | 进程生命周期、本地服务、安装包与系统集成 |

两者可 **共用** 你从 `server.mjs` 抽出的 **JSON API**；桌面端也可继续 **整页加载** `index.html`，学习重点在 **壳与进程**，而非重写前端。

---

## 九、学习顺序小结

1. 里程碑 1：壳 + 手动后端，验证加载与调试流程。  
2. 里程碑 2：`spawn` + 端口就绪 + 退出清理。  
3. 里程碑 3：环境变量、安全默认、可选托盘/单实例。  
4. 里程碑 4：安装包；有条件再加自动更新。
